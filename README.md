# 安心用药 AnxinMed · Demo

> 「安心用药 AnxinMed」MVP 演示版本 —— 把一个人所有来源的药放进同一个药箱：**管依从、管冲突、管效期**。
> 本 Demo 对应 `docs/06-安心用药-产品需求文档-PRD-V2.md`（V2），用于验证**双线拍照录入、草稿确认页、服药计划与提醒、相互作用检查、说明书库按键取数的 AI 咨询**等核心能力与安全规则。Demo 使用 Mock 三库（药品身份库 / 说明书库 / 相互作用规则库），所有数据仅保存在本机浏览器，**不用于真实诊疗、处方或用药决策**。

---

## 一、产品定位

解决**长期、多药、多来源用药人**的依从性与用药安全：一个病在一个医院看、另一个病在其他医院看，还自购 OTC——没有任何一方掌握完整用药清单。安心用药把所有来源的药放进同一个药箱：处方笺拍照建立医嘱计划，按时提醒并记录依从性，跨院药物自动做冲突检查，长期用药的库存与效期持续管理。

**安全优先**的原则（V2 §1.3）：

- 宁可无法识别，也不猜测药品；识别结果必须经用户确认后才可使用；
- **医嘱只抄录，不生成**——用量、频次、疗程只能来自用户确认的处方/标签文本或用户自填；
- 药盒/说明书上的用法用量不作为医嘱来源（药盒层不提取用法用量）；
- 规格冲突必须暴露，系统不选边；遮挡/涂黑字段按缺失处理，不猜测补全；
- AI 只基于已确认信息和本地说明书库回答；不诊断、不预测个体疗效；高风险场景优先引导医生、药师或急救；
- **凡进档案，最后一道门是用户**——药品、健康信息、计划同此。

## 二、V2 核心流程：双线拍照录入

### 两个显式入口（对应两种用户意图）

| 入口 | 意图 | 产出 |
| :-: | :-- | :-- |
| **A · 拍处方笺** | 把这次看病开的药安排上 | 档案 + 完整计划草稿（仅缺服药时间点） |
| **B · 拍药品** | 我手里这个药，帮我建档管理 | 贴标药盒：建档 + 标签抄录的计划草稿；自购 OTC：仅建档，计划手动建 |

### 双线提取（服务端 `/api/extract`）

```
拍照上传（单张）
  ├─ 层检测：{处方层|医院标签层|药盒原装层|说明书层|不支持}
  │    └─ 作为入口校验：与所选入口不符时提示确认或切换，不静默改道
  ├─ 医嘱线（处方层/医院标签层）：OCR → 版面裁剪（Rp 锚点）→ 白名单解析（正则）→ 兜底脱敏
  │    └─ 抽不出的项走「原文人工补」，不预填猜测
  ├─ 身份线（所有层）：VLM 提取身份 → 药名+规格+剂型三项严格匹配
  │    └─ 任一冲突/多候选进入冲突清单，不自动裁决；批准文号仅作平局裁判
  └─ 草稿汇合：档案草稿 + 计划草稿 + 健康信息建议 + 相互作用检查 + 说明书范围校验
```

### 草稿确认页（唯一闸门）

- 处方/标签**原文 ↔ 结构化字段并排**（真实上传显示图片；演示样例显示脱敏后的原文文本）；
- **用量/频次/疗程无差别逐项核对**（核对勾选）；
- **四类标注**：抄录 / 辅助（时间点建议）/ 推算（结束日期、库存天数）/ 默认（开始日期）；
- **冲突清单**：多规格（0.1% vs 0.2%）、层间冲突（标签 200 滴 vs 盒面约 300 滴）——用户选择，系统不选边；
- 疗程缺失时**三选一**：长期服用（开放式）/ 用完为止（按库存推算）/ 自定义天数（封闭式）；
- 健康信息「建议填入」勾选区（勾选才写入，字段级来源标注）；
- 相互作用检查（新计划 × 当前生效计划集合）与说明书范围校验结果；
- 处方患者信息与资料不一致时提示「这是给谁用的药」；
- 四层脱敏执行面板（L0 版面裁剪 / L1 白名单 / L2 兜底扫描 / L3 出口约束）；
- 确认动作留痕：来源表（确认时间、确认方式、关键字段快照），可在「我的 → 来源与确认留痕」查看。

### 失败分支（全部"看得见地失败"）

层检测不支持（散装药片）→ 明确告知；图片质量差 → 具体重拍建议；医嘱抽取不全 → 原文人工补；身份无唯一匹配 → 冲突核对 → 手动建档（标注「未经 OCR 确认」）；信息不符 → 回到重拍或手动建档。

### 演示样例（合成化 golden case，无需照片）

| 样例 | 演示点 |
| :-- | :-- |
| 处方笺 · 海露 0.1% | 主线 golden case：1 滴×每日 4 次×共 7 天；唯一匹配；手机号兜底脱敏 |
| 处方笺 · 左氧氟沙星滴眼液 | 相互作用：与已生效的海露计划命中「需监测」（间隔 30 分钟）；患者性别不一致触发「给谁用的药」 |
| 处方笺 · 海露（多规格冲突） | 处方 0.1% vs 识别 0.2%：冲突清单暴露，用户选择，不自动选边 |
| 贴标药盒 · 海露 | 标签抄录用法、疗程缺失三选一、层间滴数冲突（200 vs 300） |
| 自购药盒 · 海露 | 仅身份线建档；药盒层不提取用法用量；计划手动创建 |

### 安全规则体系

- **L4 紧急**：命中「胸痛、呼吸困难、昏迷、儿童误服」等关键词 → 立即引导急救；
- **L3 拒答**：命中「停药、换药、增量、减量」等 → 引导联系开方医生或药师；
- **L2 受限**：模型输出含具体剂量建议 → 自动过滤；
- **L1 正常**：说明书资料解释（含药理机制）、注意事项、储存方式；
- **确认状态三档**：处方抄录确认 / OCR 唯一匹配确认（可全部咨询）；手动建档（仅 L0 资料查询，AI 个性化不可用）。

## 五、快速开始

```bash
cd demo
npm install
cp .env.example .env   # 填入 QWEN_API_KEY / BAICHUAN_API_KEY
npm run dev            # API: 8787 + Web: 5173
```

> 未配置 Key 时：录入页可用「演示样例」走完整双线管线（规则解析在服务端本地执行）；AI 咨询降级为说明书库规则拼装；药箱、计划、提醒等本地功能不受影响。

## 七、API 接口

### `POST /api/extract`

双线提取主入口。**请求体**：`{ entry: 'A'|'B', image?: dataURL, demoSample?: 样例key, activeDrugIds?: string[] }`。
**响应**：`{ layers, layerWarning, quality, sanitized[], prescription?, patientHint?, rawText?, items[] }`，每个 item 含 `identity / matchedDrug / conflicts / plan(四类标注) / healthSuggestions / rangeCheck / interactions`。

### `POST /api/draft-check`

确认页中用户解决冲突候选后重跑：`{ drugId, dose, frequency, activeDrugIds }` → `{ rangeCheck, interactions }`。

### `POST /api/interactions`

对「生效计划集合」跑规则库（计划变更时重跑）：`{ activeDrugIds }` → `{ has, items[] }`。

### `POST /api/consult`

`{ question, drug: { id, genericName, confirmStatus }, activeDrugIds }` → 结构化回答 + `citations`（药名 · 来源 · 版本）。本地说明书库按键取数；未收录时医疗搜索默认关闭（演示版不兜底）。

### `GET /api/health`、`GET /api/insight/patients`、`POST /api/insight/summary`

沿用 V1（健康检查 / 患者洞察）。

## 八、Mock 三库（数据资产，PRD V2 §13）

| 资产 | 条目 | 说明 |

| 药品身份库 `drugs` | 9 条 | 含海露 0.1%（按 `docs/data-curation/mock-hycosan-01-海露.md` 整理）、海露 0.2%（多规格陷阱演示条目）、左氧氟沙星滴眼液 |

| 相互作用规则库 `interactionRules` | 3 条 | 四级枚举（禁忌/慎用/需监测/注意）；内容只抄录，禁止模型生成 |

**药品确认状态三档**：`prescription`（处方抄录确认）/ `ocr-unique`（OCR 唯一匹配确认）/ `manual`（手动建档 · 未经 OCR 确认，仅 L0）。

## 九、数据与隐私

- 演示数据保存在浏览器 `localStorage`（`med-demo-v2-*`），不上传、不持久化到数据库；
- 上传图片仅以 Base64 直传后端调用模型，服务端不留存；OCR 原文在服务端内存中即用即弃（L3 出口约束）；
- 四层脱敏在服务端执行，审计只记剥离类型与次数；
- 「我的 → 恢复演示数据」一键清空；`.env` 已在 `.gitignore`。

## 十、使用建议

- 录入时优先使用页面上的**演示样例**体验完整流程；真实图片请拍摄平铺完整的处方笺或正面清晰的药盒；
- 确认页请**逐项核对**用量/频次/疗程再确认——识别结果不能作为服药依据；
- AI 咨询仅作说明书资料解释（含药理机制），涉及诊断、停换药或剂量调整请咨询医生或药师；
- 语音输入依赖浏览器 `SpeechRecognition`，语音播报依赖 `speechSynthesis`，建议 Chrome / Edge。
